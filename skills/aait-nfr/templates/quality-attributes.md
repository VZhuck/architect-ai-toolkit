# Quality Attributes

Closed vocabulary for the **Quality Attribute Requirements** section of a Non-Functional Requirements document. Attribute names are used verbatim — never shortened, split, merged, paraphrased, or re-cased. This catalog is not extended by tooling; adding an attribute is a deliberate human edit to this file.

A quality attribute requirement states what is measured, the threshold with its unit, and the conditions. One row per requirement in the document, identified `QAR-nn`, each traced to the business driver it serves. Priority is a baseline to start from, adjusted per project using evidence from the sources; the scale is defined in [qa-priorities.md](qa-priorities.md).

| Quality Attribute | Brief Description | Priority | Typical Metric / Fitness Function |
|---|---|---|---|
| Conceptual Integrity | The system expresses one coherent set of ideas rather than many competing ones, with the same idioms and patterns applied consistently across components. Complexity that exists is deliberate and proportionate to the problem. | P1 | ADR conformance; idiom variance review; architecture fitness tests |
| Maintainability | Cost and risk of changing the system — adding capability, fixing defects, or moving it to another platform — how readily its structure can be understood and analysed, and how well changes stay contained within module boundaries. | P0 | Lead time per change class; change impact fan-out; coupling/cohesion; MTTR for defects |
| Reusability | Components are generic enough to serve more than one system or context without modification, and can be composed without hidden dependencies. | P2 | Reuse ratio; consumers per component; duplication across systems |
| Testability | The degree to which effective test criteria can be established and run cheaply. Requires controllable inputs, observable outputs, deterministic behaviour, and reproducible builds. | P0 | Coverage %; test execution time; deterministic build rate; requirement-to-test linkage |
| Performance & Scalability | Timeliness under a given load, the resources consumed to achieve it, and the ability to absorb growth in capacity by adding or releasing resources on an acceptable cost curve. | P0 | p95/p99 latency; TPS; throughput vs. node linearity; resource per transaction; elasticity response time |
| Resilience | The system stays correct and reachable under normal conditions, survives faults and dependency failures in degraded form, and restores service and committed data within defined bounds. | P0 | Uptime %; MTBF; error-budget burn; RTO/RPO; chaos test survival |
| Security & Privacy | Protection of the system and its data from unauthorised access, disclosure, or modification, with actions reliably attributable to the actor that performed them, and personal data collected only as needed and handled per consent and regulation. | P0 | Vuln density/severity; time-to-patch; authN/authZ test coverage; PII inventory coverage |
| Auditability & Compliance | Significant events are recorded in tamper-evident, retained form sufficient to reconstruct who did what and when, and to demonstrate conformance to applicable obligations, including where formal certification is required. | P2 | Audit log completeness vs. control list; log immutability; audit findings count; certification status |
| Interoperability | Ability to exchange information with other systems — including ones unknown at design time — and use it meaningfully, without breaking existing consumers. | P1 | Standards conformance tests; contract test pass rate; breaking-change count |
| Operability | Ease of running and supporting the live system — administering it, tuning its configuration, managing capacity, understanding its internal state from external outputs, and resolving reported issues. | P1 | MTTD; manual-intervention frequency; % incidents diagnosed without new instrumentation; ticket MTTR |
| Deployability | Ease, speed, and safety of getting a change into production, including provisioning the target environment, install, upgrade, and reversal. | P1 | Deployment frequency; lead time for change; change failure rate; rollback time |
| Usability & Accessibility | Users across the widest practical range of abilities, languages, and contexts can learn the system — with documentation and assistive technologies where needed — and accomplish their goals efficiently, with few unrecoverable mistakes. | P1 | Task success rate; time-on-task; SUS score; WCAG 2.2 AA conformance; assistive-technology task completion; locale coverage |
